# Decisions: Rhythm Game Intro Screen

- Date: 2026-10-22
- Status: Confirmed

## D01. 적용 화면
- **Chosen**: 공개 홈(`/`)과 로그인 후 게임 화면(`/game`)을 함께 개선한다.
- **Rationale**: 사용자가 원하는 것은 사이트 첫 진입 경험과 실제 게임 시작 경험 모두를 리듬게임에 어울리게 만드는 것이다.

## D02. 화면의 중심 연출
- **Chosen**: 실제 플레이 전용 화면이 아니라, 노트 레인과 리듬 조명이 있는 애니메이션 스테이지 미리보기를 중심에 둔다. 기존 캐릭터와 모카 이미지도 활용한다.
- **Rationale**: 게임의 정체성을 첫 화면에서 바로 보여 주면서 기존 아트 자산을 이어 쓸 수 있다.

## D03. 공개 홈에서의 미리보기 동작
- **Chosen**: 미리보기는 장식용으로만 동작하며, 로그인이나 게임 시작을 누르기 전까지 실제 플레이나 데이터베이스 쓰기를 하지 않는다.
- **Rationale**: 방문자는 게임 분위기를 먼저 볼 수 있고, 세션 생성은 사용자가 시작을 선택한 뒤에만 이뤄진다.

## D04. `/game` 진입 흐름
- **Chosen**: 애니메이션 스테이지를 즉시 보여 주고 기존 활성 세션을 백그라운드에서 확인한다. 활성 세션이 있으면 `이어하기`, 없으면 `게임 시작`을 보여 주며, 새 세션은 사용자가 버튼을 누를 때 생성한다.
- **Rationale**: 세션 API 응답 전에도 빈 화면이 되지 않고, 사용자가 이어하기와 새 게임의 차이를 선택할 수 있다.

## D05. 세션 API 오류 처리
- **Chosen**: 세션 처리에 실패해도 스테이지를 유지하고, 화면 안에 오류 안내와 재시도 동작을 제공한다.
- **Rationale**: 현재 관찰된 500에서는 게임 영역이 사실상 빈 상태로 남았다. 로컬 확인에서 Azure CLI 토큰의 MFA 갱신이 필요했고, 사용자 인증 갱신 후 Cosmos DB 연결이 정상화됐다. 따라서 만료된 로컬 자격 증명이 이번 장애 원인으로 확인됐으며, UI는 향후의 API 오류에도 복구 가능한 상태를 제공해야 한다.

## D06. 화면 구성과 밀도
- **Chosen**: 화면을 몰입감 있는 전체 화면 스테이지로 구성하고 바깥 여백을 줄인다. 상단 영역은 작은 로고와 제목, 간단한 조작 안내 및 필수 메뉴만 둔다. 로그인/시작 버튼은 눈에 띄게 배치하고 통계는 작은 칩으로 표현한다.
- **Rationale**: 현재 화면의 과도한 제목 크기와 바깥 여백을 줄이고 시작 화면의 시각적 위계를 강화한다.

## D07. 색상과 움직임
- **Chosen**: 기존의 따뜻한 오피스 일러스트 색감을 유지하면서 민트, 노랑, 코랄 조명을 더한다. 노트가 레인을 따라 움직이고 조명·반짝임과 캐릭터에 부드러운 모션을 준다. `prefers-reduced-motion` 설정을 따른다.
- **Rationale**: 기존 브랜드 분위기를 유지하면서 리듬게임다운 생동감을 더하고, 움직임 감소 설정을 존중한다.

## D08. 홈 주 버튼과 로그인 상태
- **Chosen**: 게스트에게는 `Entra ID 로그인`, 이미 로그인한 사용자에게는 `게임 시작`을 표시한다.
- **Rationale**: 사용자의 인증 상태에 맞는 다음 행동을 첫 화면에서 바로 제공한다.

## D09. 기존 인증 및 사운드 흐름
- **Chosen**: 현재 Entra 인증 흐름을 유지한다. 사운드 재생은 명시적인 사용자 동작 이후에만 시작한다.
- **Rationale**: 기존 로그인 동작을 보존하고 브라우저의 자동 재생 제한에 맞춘다.

## 구현 중 확인할 사항
- 게임 세션 API가 로그인 후 현재 사용자 토큰으로 정상 동작하는지 재확인한다. 로컬 Azure 자격 증명 갱신 후 Cosmos 연결은 정상화됐지만, 브라우저의 인증된 세션 요청은 별도 확인이 필요하다.
- 로컬 개발 문서의 Cosmos 인증 안내와 현재 로컬 환경 설정이 일치하는지 확인한다.
