# Decisions: 사내 업무 리듬 매니저 게임

- Date: 2026-09-21
- Status: Confirmed
- Note: 초기 농구 게임 방향은 폐기하고, 아래 결정은 리듬게임 방향으로 확정한다.

## D01. 인증 테넌트 범위
- **Chosen**: 특정 조직의 Entra ID 테넌트 하나만 사용하는 단일 테넌트
- **Rationale**: 사내 서비스의 접근 범위를 명확히 하고 MVP 인증 구성을 단순화한다.

## D02. 인증 사용자 범위
- **Chosen**: 해당 테넌트의 모든 일반 사용자
- **Rationale**: 별도 그룹 승인 없이 조직 구성원이 바로 참여할 수 있게 한다.

## D03. 인증 권한
- **Chosen**: `openid`, `profile`, `email` 중심의 최소 로그인 권한
- **Rationale**: 로그인과 Entra ID 표시 이름 확인에 필요한 최소 권한만 요청한다.

## D04. 인증 구현
- **Chosen**: Microsoft 공식 MSAL 기반 인증
- **Rationale**: Entra ID와의 호환성 및 공식 지원을 우선한다.

## D05. 비로그인 사용자 경험
- **Chosen**: 소개 화면을 보여주고 `Entra ID로 로그인` 버튼 제공
- **Rationale**: 게임의 목적과 특징을 확인한 뒤 로그인할 수 있게 한다.

## D06. 순위표 사용자 표시
- **Chosen**: Entra ID의 표시 이름 사용
- **Rationale**: 별도 닉네임 설정 없이 조직 내 사용자를 식별한다.

## D07. 게임 구조
- **Chosen**: 1인용 비동기 경쟁형 리듬게임
- **Rationale**: 사용자는 자신의 기록을 만들고 조직 전체 사용자의 기록과 비교한다. 실시간 매칭 없이 실제 플레이와 경쟁을 제공한다.

## D08. 게임 콘셉트
- **Chosen**: 사무실의 리듬 매니저
- **Rationale**: 출근부터 퇴근까지의 업무를 리듬으로 처리하는 독창적인 소재로 차별화한다.

## D09. 저작권·레퍼런스 범위
- **Chosen**: 리듬세상의 고수준 재미만 참고하고, 음악·캐릭터·스테이지·연출·구체적 패턴은 독창적으로 제작
- **Rationale**: 짧은 리듬 미션과 타이밍 입력의 재미는 참고하되 기존 콘텐츠를 복제하지 않는다.

## D10. 첫 릴리스 범위
- **Chosen**: 하나의 완성도 높은 리듬 모드와 오리지널 곡 1개
- **Rationale**: 기능을 확장하기 전에 핵심 플레이 경험을 검증한다.

## D11. 곡 길이
- **Chosen**: 한 곡 2~3분
- **Rationale**: 집중력을 유지하고 반복 도전에 적합한 짧은 세션을 만든다.

## D12. 곡 음악
- **Chosen**: Web Audio API로 직접 생성하는 오리지널 비트·업무 효과음 루프
- **Rationale**: 저작권 부담을 줄이고 리듬 패턴과 판정 타이밍을 정확히 일치시킨다.

## D13. 곡 템포와 구조
- **Chosen**: 110 BPM, 4/4 박자, 8마디 단위 업무 구간 전환
- **Rationale**: 초반 학습과 후반 난이도 상승을 모두 담을 수 있다.

## D14. 업무 구간 순서
- **Chosen**: 출근 → 키보드 업무 → 메일 처리 → 회의 → 복사·문서 작업 → 퇴근
- **Rationale**: 사무실 하루의 흐름을 곡 진행과 화면 전환에 연결한다.

## D15. 리듬 패턴 데이터
- **Chosen**: 직접 설계한 고정 패턴을 JSON으로 관리
- **Rationale**: 모든 사용자가 같은 조건에서 경쟁하고 서버가 입력 이벤트를 검증할 수 있게 한다.

## D16. 핵심 입력
- **Chosen**: 스페이스바 하나로 짧은 탭과 긴 홀드 입력 지원
- **Rationale**: 조작을 즉시 이해할 수 있으면서 탭·유지 리듬을 모두 표현한다.

## D17. 홀드 판정
- **Chosen**: 누르기 시작한 시점과 떼는 시점을 모두 판정
- **Rationale**: 긴 입력의 시작과 종료 리듬을 모두 평가한다.

## D18. 판정 시간 창
- **Chosen**: Perfect ±80ms, Good ±160ms, 그 밖은 Miss
- **Rationale**: 정확도 경쟁과 초보자 접근성의 균형을 맞춘다.

## D19. 화면 표현
- **Chosen**: 2D 캐릭터·일러스트, 사무실 장면, 중앙 타이밍 게이지, 업무 아이콘과 캐릭터 동작 병행
- **Rationale**: 리듬 입력을 명확히 보여주면서 업무 소재의 유쾌한 연출을 살린다.

## D20. 접근성 표현
- **Chosen**: 판정과 타이밍을 색상·모양·텍스트·애니메이션으로 함께 표시
- **Rationale**: 색상에만 의존하지 않고 다양한 사용자가 상태를 구분할 수 있게 한다.

## D21. 난이도 곡선
- **Chosen**: 초반은 쉽게 시작하고 후반으로 갈수록 점진적으로 어려워지는 고정 패턴
- **Rationale**: 학습과 긴장감을 한 곡 안에서 자연스럽게 제공한다.

## D22. 점수
- **Chosen**: Perfect 100점, Good 60점, Miss 0점
- **Rationale**: 정확한 입력을 명확히 보상하면서 계산을 단순하게 유지한다.

## D23. 콤보 점수 배율
- **Chosen**: 10콤보마다 0.1배 증가, 최대 1.5배
- **Rationale**: 연속 성공을 보상하되 한 번의 실수로 점수 격차가 과도하게 커지는 것을 막는다.

## D24. Good과 콤보 처리
- **Chosen**: Good은 일반 콤보를 유지하지만 Perfect 연속 카운트에는 포함하지 않음
- **Rationale**: 초보자의 콤보 부담은 낮추면서 Perfect 연속 보상은 보호한다.

## D25. 하트와 Miss 처리
- **Chosen**: 시작 하트 5개, Miss마다 1개 감소, 하트 0개면 곡 중도 종료
- **Rationale**: 실수 여유와 긴장감을 함께 제공한다.

## D26. 하트 회복
- **Chosen**: Perfect 10회 연속마다 하트 1개 회복, 최대 5개
- **Rationale**: 정확한 플레이를 보상하되 회복이 너무 쉬워지지 않게 한다. Miss 또는 Good은 Perfect 연속 카운트를 초기화한다.

## D27. 튜토리얼
- **Chosen**: 첫 진입 시 30초 이내 인터랙티브 튜토리얼 제공
- **Rationale**: 탭·홀드·판정·일시정지를 직접 연습하게 한다.

## D28. 일시정지
- **Chosen**: 화면 버튼과 `Esc` 키 제공, 브라우저 뒤로가기·탭 전환·창 최소화도 자동 일시정지
- **Rationale**: 입력 누락을 방지하고 사용자가 안전하게 게임을 멈출 수 있게 한다.

## D29. 중간저장·이어하기
- **Chosen**: 정확히 일시정지된 시점의 곡 위치, 하트, 콤보, 점수와 게임 상태를 서버에 저장하고 복원
- **Rationale**: 새로고침·탭 종료·뒤로가기를 해도 게임이 초기화되지 않도록 한다.

## D30. 세션 저장 규칙
- **Chosen**: 주요 이벤트마다 저장하고 이동·재생 중에는 주기적으로 저장; 사용자당 진행 중 게임 1개만 허용
- **Rationale**: 복원 정확도와 서버 부담의 균형을 맞추고 진행 세션을 명확히 관리한다.

## D31. 게임 포기
- **Chosen**: 별도의 `게임 포기` 버튼을 제공하고 확인한 경우에만 진행 세션 폐기
- **Rationale**: 사용자가 명시적으로 선택했을 때만 게임을 초기화한다.

## D32. 결과 기록
- **Chosen**: 모든 플레이 기록을 저장하고 순위표에도 표시; 한 사용자가 여러 순위를 차지할 수 있음
- **Rationale**: 반복 도전 자체를 경쟁 기록으로 남긴다.

## D33. 중도 종료 기록
- **Chosen**: 하트 0개로 종료된 기록도 저장하되 완주 여부를 구분
- **Rationale**: 실패 기록도 플레이 이력과 분석에 활용한다.

## D34. 순위표 정렬
- **Chosen**: 최종 점수 내림차순 → Perfect 개수 → 플레이 시간 순
- **Rationale**: 점수, 정확도, 효율을 함께 반영한다.

## D35. 순위표 기간
- **Chosen**: 오늘의 순위와 전체 누적 순위를 함께 제공
- **Rationale**: 일일 경쟁과 장기 기록 경쟁을 모두 지원한다.

## D36. 점수 검증
- **Chosen**: 서버가 고정 리듬 패턴과 입력 이벤트를 검증한 뒤 최종 점수를 저장
- **Rationale**: 클라이언트가 보낸 점수 조작을 방지한다.

## D37. 기록 보관
- **Chosen**: 최종 순위 기록은 계속 보관하고 원본 입력 이벤트는 90일 보관 후 정리
- **Rationale**: 순위 경쟁 기록은 유지하면서 검증용 데이터의 저장 비용을 관리한다.

## D38. 오디오 설정
- **Chosen**: 음악 볼륨·효과음 볼륨·음소거를 각각 제공
- **Rationale**: 사내 환경과 사용 상황에 맞춰 음량을 조절할 수 있게 한다.

## D39. 오디오 보정
- **Chosen**: 사용자별 오디오·입력 지연 보정 설정 제공
- **Rationale**: 브라우저와 기기별 오디오 지연으로 인한 판정 불공정을 줄인다.

## D40. 기술 스택
- **Chosen**: TypeScript + React/Next.js + Phaser
- **Rationale**: 인증·소개·순위표는 Next.js/React로, 실제 리듬 플레이는 Phaser로 구성한다.

## D41. Azure 배포
- **Chosen**: Azure App Service
- **Rationale**: Next.js 서버, Entra ID 연동, Cosmos DB 접근을 한곳에서 운영한다.

## D42. 데이터베이스
- **Chosen**: Azure Cosmos DB API for NoSQL; 진행 세션과 완료 결과를 별도 문서로 저장
- **Rationale**: JSON 게임 상태를 유연하게 저장하고, 자주 갱신되는 진행 상태와 순위 조회용 결과를 분리한다.

## D43. 비밀값 관리
- **Chosen**: Azure Key Vault + App Service Managed Identity
- **Rationale**: Entra ID·Cosmos DB 비밀값을 코드와 배포 설정에서 분리한다.

## D44. 공식 지원 환경
- **Chosen**: 최신 Chrome·Microsoft Edge 데스크톱, 16:9 기준 반응형 화면
- **Rationale**: Web Audio API와 키보드 입력을 안정적으로 지원하면서 일반적인 데스크톱 화면에 대응한다.

## D45. 관리자 기능
- **Chosen**: 첫 버전에는 관리자 화면을 포함하지 않음
- **Rationale**: 고정된 곡·패턴으로 핵심 플레이 경험을 먼저 완성한다.

## D46. Azure 준비 상태
- **Chosen**: Entra 테넌트와 Azure 구독이 이미 있으며 필요한 리소스를 생성할 수 있음
- **Rationale**: 실제 인증·Cosmos DB·App Service 연동을 초기 구현 범위에 포함할 수 있다.
